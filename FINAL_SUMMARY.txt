❓ YOUR QUESTION ANSWERED

Q: How to use pagination concept from StateController in dropdowns?

A: Three approaches based on dataset size:

   1️⃣  SMALL DATASETS (< 100 items) - e.g., States
       ✓ No pagination needed
       ✓ Load all records once on page load
       ✓ Cache in memory
       ✓ Use simple <select> dropdown
       
   2️⃣  MEDIUM DATASETS (100-1000) - e.g., Clients  
       ✓ Server-side pagination (25-50 per page)
       ✓ Add search box for filtering
       ✓ Show pagination buttons below dropdown
       ✓ Load page on demand
       
   3️⃣  LARGE DATASETS (1000+) - e.g., Cases
       ✓ Implement infinite scroll
       ✓ Virtual scrolling for performance
       ✓ Auto-load more items as user scrolls
       ✓ Cache loaded items

📋 IMPLEMENTATION PATTERN (CQRS)

Both controllers follow the established pattern from CourtTypeController:

   HTTP Request
        ↓
   [Controller Method]
        ↓
   Create Command/Query Object
        ↓
   Send via Mediator.Send()
        ↓
   Handler processes (validation, business logic)
        ↓
   Return Result<T>
        ↓
   Controller converts to HTTP Response
        ↓
   HTTP Response (with proper status code)

Example:
   POST /api/v1/client → CreateClientCommand → CreateClientCommandHandler
   ↓ (validates & creates)
   Returns Result<Guid> → Controller wraps → 201 Created response
